# 排查：为什么生成报告后列表又空了

现象：每次生成报告后，访问 https://www.chuckfan.com/reports 显示「报告列表为空：服务器 /data/reports/index.json 无内容」。

---

## 原因

**一定有某段代码在「写」或「覆盖」`/data/reports/index.json`**，且写成了空或无效内容。常见情况：

1. 管道里**先清空再追加**写 index，结果只写了一条或写入失败 → 文件变空或损坏  
2. 管道里**自己拼 JSON** 写 index，漏写、格式错、异常中断 → 空文件或非法 JSON  
3. 生成报告前**删除或覆盖** index.json  
4. 管道**从未调用**全量扫描脚本，只依赖上面某种「自己写 index」的逻辑

本仓库**不会**写 index.json，只提供「全量扫描后写 index」的脚本。写坏 index 的代码一定在**报告生成管道**里（DMIT 服务器上的脚本、Telegram Bot、stock_report_generator 等）。

---

## 在服务器上快速确认

SSH 到报告所在服务器后执行：

```bash
# 1. 报告根目录（按你实际路径改）
cd /root/data/reports

# 2. 当前 index.json 是否为空或很小
ls -la index.json
cat index.json | head -c 200

# 3. 是否有各股票的 review_latest.json（说明报告其实生成了）
ls -d */ | head -5
ls 002173/review_latest.json 2>/dev/null && echo "有 review_latest.json"

# 4. 用手动执行全量脚本恢复列表（路径按实际改）
python3 /path/to/chuck-s-lego-world/scripts/build_report_index.py /root/data/reports
# 或
REPORTS_ROOT=/root/data/reports /path/to/chuck-s-lego-world/scripts/pipeline_update_index.sh

# 5. 再刷新网站 /reports，若此时列表正常 → 说明是管道里某处在覆盖 index，需要按下面改管道
```

若第 4 步执行后列表正常，就可以确定：**管道里在写 index，且没用好，需要改成「只调用全量脚本」**。

---

## 找到管道里写 index 的代码

在**生成报告的那套代码**里搜索（报告生成脚本、Bot、cron 调用的脚本等）：

```bash
# 在管道项目或服务器上
grep -r "index.json" --include="*.py" --include="*.sh" .
grep -r "reports.*index\|index.*reports" --include="*.py" --include="*.sh" .
grep -r "json.dump\|open.*w.*json\|write.*index" --include="*.py" .
```

重点看：

- `open(..., 'w')` 且路径含 `reports` 或 `index.json`
- `json.dump(..., 某文件)` 且目标是 index
- 先读 index → 追加一条 → 再写回（这种容易写空或写坏）
- 生成前 `os.remove` 或清空 index 的逻辑

**把这些「写 index」的逻辑全部删掉**，只在**所有** `review_*.json` 写完后，**加一步**调用全量脚本（见 [PIPELINE-INTEGRATION.md](PIPELINE-INTEGRATION.md)）。

---

## 正确做法（小结）

1. **删除**管道里所有写 `/data/reports/index.json` 的代码。  
2. 在**每次**写完当次所有 `review_*.json`（和 md/html）后，**只**执行一次：
   - `REPORTS_ROOT=/root/data/reports /path/to/chuck-s-lego-world/scripts/pipeline_update_index.sh`  
   - 或  
   - `python3 /path/to/chuck-s-lego-world/scripts/build_report_index.py /root/data/reports`  
3. 路径 `/root/data/reports`、`/path/to/chuck-s-lego-world` 改成你服务器上的实际路径。

详细步骤和复制粘贴示例见 **[PIPELINE-INTEGRATION.md](PIPELINE-INTEGRATION.md)**。
